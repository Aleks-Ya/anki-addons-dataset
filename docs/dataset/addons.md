# Addon fields

Notes on the fields of the main table (`data.parquet`, config `default` on HuggingFace), one row per addon.
Back to the [dataset card](https://huggingface.co/datasets/Ya-Alex/anki-addons).

## AI-generated fields
`ai.summary` (one sentence) and `ai.tags` (picked from the vocabulary in the [`tags` table](tables.md#tags):
function tags such as `scheduling`, status tags such as `obsolete` or `paid`) are generated by a large language
model (`ai.model`) from the AnkiWeb description and the GitHub README, not written by the author. They may be
inaccurate. All other fields are collected, except where a `*_source` or `evidence` field says `ai`.

## Description
`anki_web.description` is plain text. `anki_web.description_html` is the author's HTML with absolute links,
**not sanitized**: sanitize it before rendering. `anki_web.description_pre_wrap` is `true` when AnkiWeb renders
the description with preserved line breaks (CSS `white-space: pre-wrap`).

## Author
AnkiWeb publishes no authors, so `author` groups the addons linked through the addon pages' "The author has
shared N other item(s)" lists. `author.id` is the smallest addon ID in the group: an anonymous label that can
change between snapshots. `anki_web.other_items_count` is that N, shared decks included.

## GitHub repo and forum topic
`github` and `forum` describe the addon's own repo and topic, or are `null` when none was found.
`github.repo_source` and `forum.topic_source` say how it was chosen:
- `override`: set by hand
- `contact_author`: the Contact Author link of the addon page
- `self_reference` (repo): the only linked repo that mentions the addon ID
- `ai`: linked from the description and chosen or confirmed by a large language model
- `most_linked`: linked from the description most often, not confirmed
- `title_match` (topic): a forum Add-ons topic the page does not link, matched by title and confirmed by a large
  language model

## Shared repos
Several addons can have the same `github` repo: a repo holding many addons, the same addon listed twice, or a fork
that links its original. `github.shared_with` lists the other addons of the snapshot with the same repo (empty when
the repo is not shared), and `github.repo_sharing` is `same_author` or `cross_author` when the repo is shared,
`null` otherwise or when an author is unknown. All repo-level fields (stars, issues, commits, releases, ...) repeat
across `shared_with`: count each repo once before summing them.

## GitHub activity
- `github.release_downloads` sums the asset downloads of the newest 100 releases: real install numbers, but only
  for addons distributed through GitHub releases.
- `github.contributors` counts only commits made with a GitHub account and stops at 100.
  `github.weekly_commits` covers the last 52 weeks, oldest first, and is `null` when GitHub had not computed it yet.
- `github.open_issue_count`, `github.closed_issue_count`, `github.open_pr_count`, `github.closed_pr_count` (closed
  without merging) and `github.merged_pr_count` are GitHub's totals; `github.open_issues` mixes open issues with
  open pull requests.
- `github.median_first_response_hours` covers the newest 100 issues and 100 pull requests, leaving out bot and
  unanswered items, so a low median can hide many ignored issues: check `github.first_response_sample`.
- `github.outside_pr_merge_share` is the share merged among the decided pull requests of outside authors (not a
  bot, owner, organization member or collaborator) in the newest 100.

## Forks
`forked_from` is the addon this one was forked from, with its `evidence`: `github_fork` (the GitHub repo is a fork
of the other addon's repo), `ai` (a large language model found it to be a modified copy of an addon it links) or
`override`. `forks` lists the addons forked from this one. Detection is incomplete and `ai` evidence may be
inaccurate. `github.fork_count` is unrelated: the GitHub fork count of the repo.

## Package
The `package` field summarizes the addon branch with the highest `min_point_version` in the
[`packages` table](tables.md#packages) and adds `primary_language` (the language with the most bytes, ignoring
data formats such as `JSON` or `YAML`). Languages have the same names as in `github.language_bytes`. It is `null`
when the snapshot holds no package of the addon.
`anki_web.package_size_kb` is the size shown by AnkiWeb, rounded to 10 kB (`0` means under 10 kB).

## Older snapshots
Fields and tables added after a snapshot was collected are `null` or empty in it.
