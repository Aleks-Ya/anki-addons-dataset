## Introduction

[Anki flashcard program](https://apps.ankiweb.net) has more than [2 thousand addons](https://ankiweb.net/shared/addons).  
This dataset contains information about these addons including data from
the [Addon Catalog](https://ankiweb.net/shared/addons), [GitHub](https://github.com/Aleks-Ya/anki-addons-dataset), and [Anki Forum](https://forums.ankiweb.net).  
Usually, the dataset is updated once a month.

The `ai.summary` field is a one-sentence description **generated by a large language model** from the
AnkiWeb description and the GitHub README, not written by the addon author. The model that produced
it is recorded in `ai.model`. It may be inaccurate: treat it as a convenience for browsing, not as a
statement by the author. The `ai.tags` field is generated the same way: the model picks the addon's tags
from a fixed vocabulary (function tags such as `scheduling` or `statistics`, and status tags such as
`obsolete` or `paid`). The full vocabulary with the meaning of every tag is the `tags` table
(`latest/parquet/tags.parquet`, also in Excel). All other fields are collected, not generated.

The `anki_web.description` field is the AnkiWeb description as plain text. The `anki_web.description_html`
field is the same description as the author's HTML (the inner HTML of the description block, `null` when
there is none). It is **not sanitized**: sanitize it before rendering. Relative links and image sources are
made absolute against the addon's AnkiWeb page; images stay as URLs. `anki_web.description_pre_wrap` is
`true` when AnkiWeb renders the description with preserved line breaks (CSS `white-space: pre-wrap`), which
it does for addons last updated before August 2023.

AnkiWeb publishes no author names or IDs, so the `author` field is derived. Each addon page links to a list of
the items its author has shared ("The author has shared N other item(s)"), and addons connected through these
lists are grouped under one author. `author.id` is the smallest addon ID in the group: an anonymous label, not
an AnkiWeb identifier. It changes when that addon is removed or the author publishes an addon with a smaller ID.
`author.addon_count` is the number of the author's addons in the snapshot. `author` is `null` in snapshots
collected before authors were tracked. `anki_web.other_items_count` is the "N" from the addon page, available
in every snapshot; it counts shared decks as well as addons.

Abandoned addons are often forked and republished under a new name. `forked_from` is the addon an addon was
forked from, or `null`, with its `evidence`: `github_fork` when the addon's GitHub repo is a GitHub fork of
another addon's repo (`github.fork_source` holds the root repo), `ai` when a large language model read the
AnkiWeb description and found that the addon is a modified copy of an addon it links to, or `override` when
set by hand. An addon has at most one parent; when GitHub and the AI disagree, GitHub wins. `forks` is the
reverse: the addons that were forked from this one, any number of them. Detection is incomplete: a fork
that neither uses a GitHub fork nor links the original from its description is not found, and `ai` evidence
may be inaccurate.

The `anki_versions` table (`latest/parquet/anki_versions.parquet`, also in Excel) lists the stable
Anki releases from 2.1.0 on, newest first, taken from the tags of the [Anki repository](https://github.com/ankitects/anki)
when the snapshot was collected (betas and release candidates are left out). `version` is the version as Anki
writes it (`25.09.2`, `2.1.66`), `point_version` is Anki's integer encoding of it, which sorts correctly
(`2.1.x` → `x`, `YY.MM.PP` → `YYMMPP`, so `2.1.66` → `66` and `25.09.2` → `250902`), the same encoding as the
`*_point_version` fields of the addons. Snapshots collected before the table was introduced have no
`anki_versions` files.

The `reviews` table (`latest/parquet/reviews.parquet`) holds the user reviews from the AnkiWeb
addon pages, one row per review, sorted by `addon_id` and then newest first: `addon_id`, `date`, `vote`
(`like` or `dislike`), `text` (empty for a review left without text) and `author_reply` (the addon author's
comment, or `null`). AnkiWeb does not show who wrote a review, so the table has no reviewer column. The page-wide
`likes`/`dislikes` counts of the main table can differ slightly from the votes of the listed reviews.

Questions, feedback, bugs: [Support page at Anki Forum](https://forums.ankiweb.net/t/anki-addons-dataset-a-detailed-list-of-addons/63090)

## Files
### Structure
Folder `history` contains data files for each day when the dataset was updated.  
Folder `latest` contains the most recent day from `history`.
```
├── history
│   ├── YYYY-MM-DD
│   │   ├── parquet
│   │   │   ├── anki_versions.parquet
│   │   │   ├── data.parquet
│   │   │   ├── reviews.parquet
│   │   │   └── tags.parquet
│   │   ├── xlsx
│   │   │   ├── anki_versions.xlsx
│   │   │   ├── data.xlsx
│   │   │   └── tags.xlsx
│   │   ├── metadata.json
│   │   ├── raw.zip
│   │   └── stage.zip
├── latest
│   ├── parquet
│   │   ├── anki_versions.parquet
│   │   ├── data.parquet
│   │   ├── reviews.parquet
│   │   └── tags.parquet
│   ├── xlsx
│   │   ├── anki_versions.xlsx
│   │   ├── data.xlsx
│   │   └── tags.xlsx
│   └── metadata.json
└── README.md
```

### Excel
The best for **manual analysis** in Microsoft Excel or LibreOffice Calc.  
Location: `latest/xlsx/data.xlsx`, `history/YYYY-MM-DD/xlsx/data.xlsx`

### Parquet
The best for **programmatic analysis** by Python, etc.  
Location: `latest/parquet/data.parquet`, `history/YYYY-MM-DD/parquet/data.parquet`

### JSON
No longer published: Parquet holds the same data. The JSON files of the snapshots up to 2026-10-01 remain
in the Git history of this repository.

## Raw and Stage data
Raw data (collected during the dataset construction) are available in `history/YYYY-MM-DD/raw.zip`.  
It includes HTML pages of the Addon Catalog, responses of GitHub REST API (including the tag list of the
Anki repository behind the `anki_versions` table), responses of Anki Forum API,
and the cached AI answers behind `ai.summary` and `ai.tags` (each keyed by a hash of the prompt, which is not stored).  
Structure of the raw data:
```
raw-metadata.json
1-anki-web/
    addons_page.html
    addon/{addon-id}.html
2-github/{user}/{repo}/
    actions.json
    info.json
    languages.json
    last-commit.json
    tree.json
2-github/ankitects/anki/tags.json
3-forum/topic/{topic_id}.json
4-ai/ai-cache.jsonl
```

Stage data (intermediate data generated during the dataset construction) are available in `history/YYYY-MM-DD/stage.zip`.  
File `4-overrider/overrides.yaml` contains manually curated data which override automatically parsed values.  
Structure of the stage data:
```
1-anki-web/addon/{addon-id}.html
2-github/{user}/{repo}/
    action-count.json
    languages.json
    last-commit.json
    stars-count.json
    tests-count.json
3-enricher/
    forum/{addon-id}.json
    github/{addon-id}.json
4-overrider/overrides.yaml
```
