# Skill update-uml-diagrams
Re-generate UML diagrams from the source code.

## PlantUML documentation
Class diagrams: https://plantuml.com/class-diagram
Deployment diagrams: https://plantuml.com/deployment-diagram

## Diagrams location
1. `doc/uml/ai`: diagrams generated by AI. Update these.
2. `doc/uml/human`: diagrams created by humans. Never write here — not even a file whose name matches
   one you are updating (`class-all.puml` and `packages.puml` exist in both folders). Read them for
   which relationships the author considers important.

## Precondition
```bash
plantuml -version
```
If the `plantuml` CLI is not installed, tell the user it is missing and **stop** — do not edit any
diagram. Check this before making changes, not after.

## Source of truth
The class and folder inventory always comes from `src`, read fresh on every run — never from the
current contents of the diagram. `CLAUDE.md` is a good guide to which relationships matter.

Ignore `tests/`, `tests_integration/`, `*.egg-info`, `__pycache__`, and any directory with no `.py`
file of its own.

## Completeness
Enumerate the real inventory from `src`, compare it with what the diagram declares, then **add**
what is missing and **delete** what no longer exists, including relationships that referenced it.
Deleting is the step that gets skipped, and it is why the diagrams drift.

## Conventions
Preserve what the files already do, so a re-generation diffs small:
1. Keep the `title ... (by AI)` line and the `skinparam`/`hide` block.
2. Keep the existing nesting and ordering; insert new entries alphabetically within their package.
3. Keep the `' Comment` headers grouping the relationships; add to the section a relationship belongs to.
4. Stereotypes: `<<dataclass>>`, `<<NewType>>`, `abstract class` for ABCs, `enum` for enums.

## Guidelines for updating individual UML diagrams

### Diagram `doc/uml/ai/class-all.puml`
1. It uses the syntax of a class diagram.
2. It shows Python classes in `src`, in packages mirroring the folders of `src`.
3. `hide empty members` is set and class bodies stay empty: no attributes, no methods.
4. Show inheritance (`--|>`), composition (`*--`, `o--`) and usage (`-->`), not every import.

### Diagram `doc/uml/ai/class-addon-infos.puml`
1. It uses the syntax of a class diagram.
2. It shows the structure of the AddonInfos domain model (src/anki_addons_dataset/common/data_types.py).
3. Unlike `class-all.puml`, it lists every field with its declared type.

### Diagram `doc/uml/ai/packages.puml`
1. It uses the syntax of a deployment diagram.
2. Create a PlantUML diagram of dependencies between folders in `src`, derived from the `import`
   statements: an edge A → B means a module in A imports a module in B.
3. Only show an edge when neither folder is an ancestor of the other (this excludes self-, inner-folder
   and parent-folder dependencies).
4. Make arrows red.

## Verify
```bash
plantuml -checkonly doc/uml/ai/*.puml
```
Fix what it reports and re-run until silent.

## Done
Report per diagram: classes (or folders) added, deleted, and the `plantuml -checkonly` result.
